# SEO/GEO: эксплуатация и перенос

Подготовлено 22.10.2026. Сайт статический: содержимое, цены и метаданные доступны в исходном HTML без исполнения JavaScript. Генератор работает на Python 3 без сторонних зависимостей.

## Единые источники

- `seo.config.json` — основной HTTPS-адрес, название, телефон, адрес студии, официальные профили, изображение и цвет браузера.
- `dist/content/prices.json` — 73 записи каталога DIKIDI, исходные ID, длительности, цены и дата последней фактической сверки. Цена курса за сеанс отделена от полной стоимости курса.
- `dist/content/articles.json` — карточки, состояние и будущие тексты статей.
- `scripts/prepare_seo.py` — шаблоны направлений и генерация HTML, метаданных, JSON-LD, sitemap, robots и версии офлайн-кеша.
- `seo-state.json` — отпечатки содержимого и реальные даты изменения. Хранить в Git; не удалять при каждой сборке.
- `seo-pages.json` — автоматически создаваемая опись страниц и правил индексации.

## Обновление

После фактической сверки каталога измените JSON и `verified_at`. Затем выполните:

```sh
python scripts/prepare_seo.py
python scripts/check_seo.py
python scripts/check_static_content.py
python scripts/test_seo_pipeline.py
node --check dist/app.js
node --check dist/sw.js
```

Генератор обновляет страницы шести направлений, полный прайс, цены в модальных окнах, JSON-LD и sitemap из общего каталога. Самостоятельного фонового запроса DIKIDI, расписания обновления цен, мониторинга позиций или отправки страниц в поисковики нет. Вводные тексты и ответы также нужно сверять, если меняется ассортимент.

### Доступность для Яндекса без исполнения JavaScript

Проверка `check_static_content.py` входит также в основной `check_seo.py`. Она читает основной HTML и не засчитывает текст из JavaScript, JSON-LD, шаблонов, скрытых элементов и модальных окон как содержимое страницы. В HTML проверяются названия, цены и длительность всех 73 позиций полного прайса и всех процедур на шести страницах направлений. Девять готовых индексируемых страниц достижимы от главной по обычным ссылкам без скриптов. Закрытые блоки прайса используют нативные `details` и содержат строки сразу, а не загружают их при нажатии.

Будущие опубликованные статьи проверяются на наличие текста разделов непосредственно в HTML. Регрессионные проверки отдельно выявляют перенос прайса в скрытый шаблон и удаление видимых названий при сохранённой JSON-LD-разметке. Это проверка доступности содержимого, а не подтверждение фактической индексации или позиции в поиске. Сравнение версий страницы с рендерингом и без него в Яндекс Вебмастере выполняется после публикации на открытом основном домене.

Официальные пояснения: https://yandex.ru/support/webmaster/ru/yandex-indexing/rendering и https://yandex.ru/support/webmaster/ru/robot-workings/vision .

## Публикация статьи

Скопируйте структуру `content-drafts/article-template.json` в каталог статей. До проверки редактором оставляйте `status: coming_soon`: это заглушка без Article-разметки, индексации и включения в sitemap.

Для публикации нужны `status: published`, `editorial_approved: true`, реальный автор, непустые разделы и даты с часовым поясом. Дата обновления не может быть раньше даты публикации. Изображение, если указано, требует фактических `image_width`, `image_height` и описания. Источники задаются списком `sources`. Медицинские утверждения необходимо согласовать с квалифицированным специалистом; программная проверка не заменяет редакционную.

После генерации появляются видимый текст, автор, дата, хлебные крошки, обычные ссылки, BlogPosting и URL в sitemap. Каталог статей становится индексируемым, когда опубликован хотя бы один материал. Не меняйте дату материала без содержательной причины. При снятии публикации пересоберите сайт: страница снова получает noindex и исчезает из sitemap.

## Перенос на основной домен

Подставьте свой реальный домен вместо примера:

```sh
python scripts/prepare_seo.py --base-url https://your-domain.example
python scripts/check_seo.py
python scripts/test_seo_pipeline.py
```

Команда сохраняет домен в конфигурации и синхронно обновляет canonical, Open Graph, Schema.org, адреса видимой микроразметки и sitemap. Публиковать нужно содержимое `dist`, а не весь репозиторий. Проверки запускать до выкладки. Скрипты сами сайт не публикуют.

`deploy/nginx.conf.example` — заготовка для администратора сервера. Заполнить DOMAIN, DOCUMENT_ROOT и пути сертификатов, проверить `nginx -t` на целевом сервере и только затем применять. Заготовка в текущей среде не применялась и Nginx не проверялась.

После переноса проверить:

1. HTTPS и единственный основной вариант домена. HTTP, www и `/index.html` перенаправляются 301 на выбранный адрес без цепочек. Для неизвестной страницы сервер отдаёт HTTP 404 с `404.html`, а не главную с кодом 200.
2. Полезные страницы, CSS, JS и изображения доступны роботам без входа и блокировок CDN/WAF. Наличие Allow в robots не снимает авторизацию хостинга.
3. `/robots.txt` и `/sitemap.xml` доступны с кодом 200. В sitemap только основной домен и готовые страницы; на них нет noindex.
4. Добавить и подтвердить домен в Google Search Console и Яндекс Вебмастере; отправить sitemap, запросить обход ключевых URL, проверить региональность и диагностику.
5. Проверить опубликованные URL валидатором Schema.org, тестом Google и валидатором Яндекса. Синтаксическая локальная проверка не означает подтверждение расширенного результата поисковиком.
6. Обновить сайт в официальных карточках студии в Яндекс Бизнесе, DIKIDI, VK и, когда появится профиль, 2ГИС. Согласовать название, адрес и телефон на всех площадках.
7. Проверить title, description, превью при отправке ссылки и мобильную скорость на реальном домене. Фактические Core Web Vitals доступны после накопления данных; оценка здесь не заявляется.
8. При смене уже индексированного домена настроить постраничные 301 со старых URL и процедуру переезда в кабинетах поисковиков. Текущий служебный адрес не следует объявлять основным доменом бизнеса.

## Что подготовлено для GEO

Здесь GEO включает локальный поиск и пригодность страниц для поиска с генеративными ответами. Используются понятный HTML, отдельные страницы намерений, точные локальные контакты, видимые ответы, источники, реальный автор будущих материалов и Schema.org. OAI-SearchBot разрешён в robots; настройка GPTBot для обучения не менялась. Специальный файл llms.txt и искусственные FAQ/рейтинги не добавлялись. Эти меры не гарантируют позиции, расширенный сниппет или цитирование в ответах ИИ.

Существующая аудитория предпросмотра сохранена: только владелец. Проверка открытой индексации, кабинетов поисковиков и настроек будущего сервера выполняется после переноса.
